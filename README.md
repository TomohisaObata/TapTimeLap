# TapTimeLap

FPV ドローンレース用のタップ式ラップタイマー。PWA としてビルドし、iPhone のホーム画面に
追加してフルスクリーンのアプリとして使う。

- 画面のどこをタップしてもラップを刻む（ゴーグル装着中に手探りで押せる）
- ラップタイムの日本語読み上げ＋ビープ（ベスト更新時は高音）
- タップ時の振動（iOS は 17.4〜26.4 のみ。26.5 で Apple が塞いだため以降は無反応）
- 誤タップ除け（最小ラップ時間より短い間隔のタップを無視）
- Wake Lock による画面スリープ防止
- セッション履歴の端末内保存と CSV 書き出し
- 3-2-1-GO カウントダウン（任意）
- 制限時間と終了前秒読み（任意）。走行中は各ラップ横にそのラップ通過時点の残り時間を表示
  （履歴・計測結果ではトータル/ベスト/平均のみとし、ラップ単位の残り時間は出さない）
- ラップの読み上げに残り時間を含めるか選択可（任意。「ラップ3、12.34、残り時間45.00、ベスト」の順）
- STOP 直後に「計測結果」として直前の走行を表示（履歴と同じフォーマット）

## 前提

**Node.js 20.11 以上が必要。** この端末には nvm-windows で 18.20.4 と 20.11.1 が入っている。
Node 18 では Service Worker 生成時に `crypto is not defined` で失敗するので 20 を使うこと。

nvm でのバージョン切り替えは**管理者権限の PowerShell**が必要:

```powershell
nvm use 20.11.1
```

切り替えたら確認:

```bash
node -v
```

## セットアップ

依存パッケージはインストール済み。クローンし直した場合のみ:

```bash
npm install
```

アイコンはロゴ画像（`assets/icon-source.png`）から生成している。差し替えたいときは
同じファイルを上書きしてから:

```bash
npm run icons
```

`public/icon-192.png` `public/icon-512.png` `public/apple-touch-icon.png` を書き出す。
`assets/icon-source.png` は `public/` の外に置くこと ── `public/` の中身は Service Worker が
丸ごとオフラインキャッシュするため、そこにロゴ原稿（1MB 近い）を置くとアプリが使わない
ファイルまで端末にダウンロードさせてしまう。

原稿画像は**角を丸めていない、余白なしの正方形**が理想。iOS 側で自前の角丸マスクを
かける前提のため、原稿にあらかじめ角丸や背景の余白が入っていると、その余白がホーム画面で
白い縁として見えてしまうことがある（実機で確認済み）。`build-icon.mjs` は中央から外側へ
走査して背景（白系）とロゴ本体の境界を自動検出し、余白があれば切り取ってから拡大する
フォールバックを持っているが、最初から余白なしの原稿を用意するほうが確実。

起動直後の welcome 画面に出すロゴは別ファイル（`assets/welcome-logo-source.png`）。
差し替えたいときは同じファイルを上書きしてから:

```bash
npm run welcome-logo
```

`public/welcome-logo.png`（480x480 に縮小したもの）を書き出す。こちらはアイコンと違い
OS の角丸マスクを気にする必要がないので、余白の自動検出はしていない。

ロゴがない状態から手続き的なプレースホルダー（ストップウォッチ）を作りたい場合:

```bash
npm run icons:placeholder
```

## 開発

### PC のブラウザで確認

```bash
npm run dev
```

`http://localhost:5173` を開く。`localhost` は secure context 扱いなので Wake Lock も動く。
PC では **Space / Enter キー**がタップと同じ扱いになるので、実機なしで計測フローを試せる。

### iPhone 実機で確認

同じ Wi-Fi に繋いだ状態で:

```bash
npm run dev:lan
```

`https://192.168.0.6:5173/` のような URL が出るので iPhone の Safari で開く。

- `--host` 付きのときだけ自己署名証明書で HTTPS を張る（LAN の IP は secure context ではなく、
  http のままだと Wake Lock とホーム画面インストールが動かないため）
- 初回は証明書の警告が出る。「詳細を表示」→「このWebサイトを閲覧」で進む
- IP アドレスは PC の Wi-Fi 設定で変わるので、毎回コンソールの表示を見ること

### ホーム画面に追加

Safari で開いた状態から、共有ボタン → 「ホーム画面に追加」。

これで Safari の URL バーが消えてフルスクリーンになり、横向き固定で起動する。
**ホーム画面に追加した状態で使うこと**を推奨（Safari のタブのままだと、しばらく使わないと
保存データが消える可能性がある）。

## 本番ビルドと配信

```bash
npm run build
```

`dist/` に静的ファイルが出る。バックエンドは無いので、静的ホスティングならどこでもよい。

- **Cloudflare Pages / Vercel / Netlify** — リポジトリを繋いで `npm run build`、公開ディレクトリ `dist`
- **GitHub Pages** — サブパス配信になるので base の指定が必要:

  ```bash
  BASE=/TapTimeLap/ npm run build
  ```

一度どこかに公開しておくと、飛行場で PC を開かずに iPhone だけで使える。
Service Worker が全ファイルをキャッシュするので、電波が無い河川敷でもオフラインで動く。

## 使い方

1. アプリを開く（横向き推奨）
2. 画面をタップ → 計測開始（設定でカウントダウンを ON にすると 3-2-1-GO）
3. スタート/フィニッシュゲートを通過するたびにタップ
4. 終了は右上の **STOP をタップ**
5. 自動でセッションが保存される。履歴画面から CSV 書き出し可能

### 最小ラップ時間の目安

設定の「最小ラップ時間」は誤タップ除け。**そのコースの自己ベストより 1〜2 秒短い値**にすると、
指が滑って二度押ししてもラップが割れない。既定値は 3.0 秒。

## 設計メモ

- 時刻はすべて `performance.now()`（単調増加）で扱う。`Date.now()` は端末の時刻同期でずれるので
  計測には使わない。保存用の「いつ走ったか」だけ `Date.now()` を使う
- タップ時刻は `PointerEvent.timeStamp` を採用。ハンドラが呼ばれるまでの遅延分の誤差を避ける
- 大タイマーの表示更新は `requestAnimationFrame` から DOM に直接書き込む。React の再描画を
  毎フレーム走らせない
- iOS は最初のユーザー操作の中でしか音声を有効化できないため、初回タップで `unlockAudio()` を通す
- 消音スイッチで Web Audio がミュートされるのを避けるため `navigator.audioSession.type = 'playback'`
  を宣言している（Safari 16.4+）
- 起動直後だけ「welcome」フェーズを挟む（タップすると「TapTimeLapへようこそ」と案内して
  待機画面に進む）。iOS の音声エンジンは初回起動に一定の時間がかかるらしく、開始タップと
  1本目のラップ読み上げが接近していると競合して無音になることがあった（「click 起点にすれば
  即座に解錠できる」という説を2度試したが実機では直らなかった）。welcome 画面をワンクッション
  挟むことで、実際の計測が始まる前に十分な余裕を持って音声エンジンを起こしておける。
  これにより `speak()` は pointerdown からでも click を待たず同期的に呼べるようになった
  （秒読みの「3」が以前より早く聞こえるのはこのため）
- 走行中に増減する状態（秒読み中フラグ・時間切れフラグ・LAP 表示）は React state ではなく
  ref 経由で DOM を直接書き換えている。毎秒 setState すると App 全体が再描画され、
  それ自体が体感できる描画の詰まりの一因になりうるため
- `src/lib/perf.ts` が rAF のフレーム間隔を監視し、80ms 以上の詰まりの前後4秒に起きた
  イベント（発話の開始/終了・ビープ・振動・ラップ操作）をタイムラインで記録する。
  実機でしか起きない現象を切り分けるための自己診断で、設定画面の「表示の詰まり具合」
  から確認できる。実機での検証で、読み上げ終了のちょうど2秒後に一定時間（約320ms）の
  詰まりが起きるパターンが見つかっている。iOS がオーディオ経路を解放する際の内部処理と
  みられ、JS 側からは制御できない可能性が高い。ラップタイムの記録自体は
  `PointerEvent.timeStamp` を使っているため、この詰まりによる影響を受けない
- iOS Safari は apple-touch-icon を URL 単位で長くキャッシュし、ホーム画面から一度削除
  しても更新が反映されないことがある。`vite.config.ts` がアイコンファイルの中身から
  ハッシュを計算し、`index.html` の `<link rel="apple-touch-icon">` とマニフェストの
  icon src に `?v=<hash>` を自動で付ける。`npm run icons` でアイコンを差し替えるたびに
  ハッシュが変わり、URL ごと新しいリソース扱いになるので手動でのバージョン管理は不要

## この先の拡張

- **物理ボタン対応** — キーボードとして認識される Bluetooth リモコンなら、既にある
  `keydown`（Space / Enter）ハンドラでそのまま動く。`src/App.tsx` の `onKey` が受け口
- **ネイティブ化** — Capacitor で `dist/` をラップすれば iOS アプリになる。ただし実機インストールには
  Apple Developer Program（$99/年）が必要。iPhone の**音量ボタン**でラップを刻みたくなったら
  この段階に進む（Web からは音量ボタンを取得できない）
- **iOS の電源ボタンは使えない** — Apple が公開 API を提供しておらず、ネイティブアプリでも不可能。
  押すと画面がロックされるため、そもそも計測用途に向かない
